| Year | Vulnerability | Microsoft guidance | What changed in the PAC or its validation | Enforced by default |
|---|---|---|---|---|
| 2014 | CVE-2014-6324 (MS14-068) | [KB3011780](https://learn.microsoft.com/en-us/security-updates/securitybulletins/2014/ms14-068) | The KDC's verification of PAC signatures was corrected. Before the fix a domain user could present a PAC with a forged signature and be issued tickets carrying privileged group SIDs. | On install (November 2014) |
| 2020 | CVE-2020-17049 ("Bronze Bit") | [KB4598347](https://support.microsoft.com/en-us/topic/managing-deployment-of-kerberos-s4u-changes-for-cve-2020-17049-569d60b7-3267-e2b0-7d9b-e46d770332ab) | **Ticket signature** added (PAC buffer `0x10`): a `krbtgt`-keyed checksum over the service ticket's encrypted part minus the PAC. It lets the KDC detect a service ticket that was altered before being presented back to it, for example as S4U2Proxy evidence. | July 13, 2021 updates |
| 2021 | CVE-2021-42287 (paired with CVE-2021-42278, "noPac") | [KB5008380](https://support.microsoft.com/en-us/topic/kb5008380-authentication-updates-cve-2021-42287-9dafac11-e0d0-4cb8-959a-143bd0201041) | **`PAC_ATTRIBUTES_INFO`** (`0x11`) and **`PAC_REQUESTOR_SID`** (`0x12`) added to TGTs, and a PAC is added to every TGT. During the TGS exchange the KDC checks that the client name in the TGT still resolves to the requestor SID and returns `KDC_ERR_TGT_REVOKED` if it does not. | October 11, 2022 updates |
| 2022 | CVE-2022-37967 | [KB5020805](https://support.microsoft.com/en-us/topic/kb5020805-how-to-manage-kerberos-protocol-changes-related-to-cve-2022-37967-997e9acc-67c5-48e1-8d0d-190269bf4efb) | **Extended KDC signature** added (PAC buffer `0x13`, the "full PAC signature"): a `krbtgt`-keyed checksum over the entire PAC. The older KDC signature covers only the server signature. | July 11, 2023 updates (Audit override still possible); override removed October 10, 2023 |
| 2024 | CVE-2024-26248 and CVE-2024-29056 | [KB5037754](https://support.microsoft.com/en-us/topic/how-to-manage-pac-validation-changes-related-to-cve-2024-26248-and-cve-2024-29056-6e661d4f-799a-4217-b948-be0a1943fef1) | The **PAC Validation Protocol** was hardened. This is the Netlogon path a server uses to ask a domain controller to validate a PAC, and the update also adds cross-domain filtering on that path. It did not add a PAC buffer. | January 2025 updates; Compatibility mode removed April 2025 |

These updates apply to every supported Windows Server version, not to one release. The dates are
the Microsoft enforcement dates in the linked articles; a domain controller behaves according to
the updates it has installed, not the calendar.
